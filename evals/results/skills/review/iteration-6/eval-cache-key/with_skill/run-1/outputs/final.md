I've written the review to `REVIEW.md`. My recommendation is **don't merge yet**: a customer can be charged one currency's price while being billed in another. I ran every example input in the review against the unchanged code, and the code itself is untouched. The 3 existing tests pass but don't catch any of these problems.

1. **Blocker: the price cache ignores currency** (`src/pricing.js:6`, `src/memoize.js:4`). The cache stores one price per product, so whichever currency a product is first quoted in sticks until the process restarts. For example, `quote([{sku:'CAP-03'}],'USD')` followed by `quote([{sku:'CAP-03'}],'EUR')` charges the USD price of 1500 instead of the EUR price of 1400. The tests miss this because no test quotes the same product in two currencies.
2. **Major: some invalid currencies get through and break pricing** (`src/pricing.js:9`, `src/catalogue.js:10`). The currency check also accepts built-in property names like `'constructor'` and `'toString'`. A quote in `'constructor'` returns a total of `NaN` instead of an error. Because of the cache problem in point 1, every later quote for that product then returns `NaN` in every currency until the process restarts.
3. **Moderate: quantities aren't checked** (`src/pricing.js:12`). A quantity of `-3` gives a negative total. A cart with 2 × TSHIRT-01 and -3 × MUG-02 totals 400 instead of being rejected. A quantity like `'two'` gives `NaN`, and fractional quantities are accepted. How serious this is depends on whether the code that calls `quote` checks the cart, and nothing in this repo does yet.
4. **Minor, optional: tax can come out as `-0`** for a negative USD cart. This only happens because of point 3 and disappears once that's fixed.

The review also lists what I checked and found fine (tax rounding, unknown products, defaults) and what I couldn't review (the code that calls `quote` and where its inputs come from). The review steps I was given call for an independent second review on payment code, and I didn't run one. I'd suggest a second reviewer before merging.
